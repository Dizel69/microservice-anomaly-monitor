# microservice-anomaly-monitor

Проект магистерской диссертации на тему
**«Разработка системы мониторинга микросервисов с элементами машинного обучения»**.

Репозиторий содержит **полноценный ETL-конвейер** подготовки данных для обучения
моделей обнаружения аномалий. Конвейер загружает метрики из разнородных
источников, приводит их к единому формату, очищает, рассчитывает признаки и
формирует ML-набор, пригодный для алгоритмов вида Isolation Forest.

## Архитектура

Конвейер построен по слоистой модульной архитектуре. Каждый слой имеет одну
зону ответственности, что упрощает расширение (добавление новых источников,
признаков, графиков) и сопровождение.

```
                 ┌──────────────────────────────────────────────┐
   Источники     │  NAB        KPI        Prometheus (HTTP API)  │
                 └───────┬─────────┬───────────────┬─────────────┘
                         │         │               │
                 ┌───────▼─────────▼───────────────▼─────────────┐
   loaders/      │  nab_loader   kpi_loader   prometheus_loader   │  → RAW
                 └───────────────────────┬──────────────────────┘
                                         │
                 ┌───────────────────────▼──────────────────────┐
   transformers/ │  normalize_dataframe()  (очистка, типы, NaN)  │  → PROCESSED
                 └───────────────────────┬──────────────────────┘
                                         │
                 ┌───────────────────────▼──────────────────────┐
   features/     │  add_features() / build_ml_dataset()          │  → UNIFIED + ML
                 └───────────────────────┬──────────────────────┘
                                         │
                 ┌───────────────────────▼──────────────────────┐
   visualization/│  generate_reports()  (5 графиков PNG)         │  → reports/
                 └──────────────────────────────────────────────┘

   pipeline.py — оркестрация всех слоёв; main.py — CLI.
```

## Три уровня данных

| Уровень       | Каталог               | Содержимое                                            |
|---------------|-----------------------|-------------------------------------------------------|
| **RAW**       | `datasets/raw/`       | Исходные данные источников без изменений               |
| **PROCESSED** | `datasets/processed/` | Данные после очистки и нормализации                    |
| **UNIFIED**   | `datasets/unified/`   | Единый датасет + сформированный ML-набор признаков     |
| Отчёты        | `reports/`            | Графики PNG в корне репозитория (`before/` и `current/`) |

### Куда складывать готовые датасеты

Исходные файлы раскладываются по подкаталогам источников. Можно класть
**отдельные файлы или вложенные папки** — каталог сканируется рекурсивно:

```
datasets/raw/
├── NAB/          # сюда все CSV NAB (можно во вложенных папках)
├── KPI/          # сюда все CSV KPI (Finals_dataset)
└── PROMETHEUS/   # для выгрузок Prometheus (опционально)
```

При запуске `python main.py nab` (без аргументов) обрабатываются **все** CSV
внутри `datasets/raw/NAB/` (и подпапок). Аналогично `kpi` сканирует
`datasets/raw/KPI/`. Можно также явно указать файлы/папки:
`python main.py nab path/to/dir path/to/file.csv`.

## Единый формат хранения

Все источники приводятся к шести колонкам:

| Колонка       | Описание                                                                 |
|---------------|--------------------------------------------------------------------------|
| `timestamp`   | Время измерения                                                          |
| `service`     | Имя сервиса (микросервиса / временного ряда)                             |
| `metric_name` | Тип метрики: `cpu_usage`, `memory_usage`, `disk_usage`, `http_latency`, `request_rate`, `error_rate` |
| `value`       | Числовое значение метрики                                                |
| `label`       | Метка аномалии: `0` — норма, `1` — аномалия, `-1` — неизвестно           |
| `source`      | Источник: `NAB`, `KPI`, `PROMETHEUS`                                     |

> Для Prometheus на уровне **RAW** дополнительно сохраняется колонка `labels`
> (полный набор меток серии в формате JSON) — чтобы не терять информацию о типе
> метрики и контексте.

---

## Источники данных

| Источник     | Ссылка                                                       | Метка по умолчанию |
|--------------|--------------------------------------------------------------|--------------------|
| NAB          | https://github.com/numenta/NAB                               | `0`                |
| KPI          | https://github.com/NetManAIOps/KPI-Anomaly-Detection         | из файла / `0`     |
| Prometheus   | Prometheus HTTP API (`/api/v1/query_range`, `/api/v1/query`) | `-1`               |

- **NAB**: `service` и `metric_name` выводятся из имени файла
  (`ec2_cpu_utilization_*.csv` → `cpu_usage`).
- **KPI**: `service` берётся из колонки `KPI ID`, `metric_name = kpi_value`.
- **Prometheus**: `service` определяется по меткам
  (`service`/`job`/`container`/`pod`/`instance`), `metric_name` —
  каноникализация `__name__`, все исходные метки сохраняются в `labels`.

## Инженерия признаков

Признаки рассчитываются независимо по каждому временному ряду
(группа `source` + `service` + `metric_name`) после сортировки по времени:

| Признак           | Описание                          |
|-------------------|-----------------------------------|
| `rolling_mean_5`  | Скользящее среднее (окно 5)        |
| `rolling_mean_15` | Скользящее среднее (окно 15)       |
| `rolling_std_5`   | Скользящее СКО (окно 5)            |
| `rolling_std_15`  | Скользящее СКО (окно 15)           |
| `rolling_min_5`   | Скользящий минимум (окно 5)        |
| `rolling_max_5`   | Скользящий максимум (окно 5)       |
| `delta`           | Разность с предыдущим значением    |
| `percent_change`  | Относительное изменение            |

Итоговый ML-набор (`ml_dataset.parquet` / `.csv`) не содержит пропусков в
признаках и готов к подаче в Isolation Forest, One-Class SVM, LOF и др.

## Визуализация

Графики лежат в корне репозитория, в `reports/`:

- **`reports/before/`** — снимок текущего состояния датасетов (для выступления: «как было»). Конвейер этот каталог **не перезаписывает**.
- **`reports/current/`** — графики новых прогонов ETL. Сюда смотреть после улучшения входных данных.

После ETL строятся 5 графиков **для каждого источника** (`NAB/`, `KPI/`, `PROMETHEUS/`) и **общий** набор в `combined/`:

| Файл                       | Содержание                          |
|----------------------------|-------------------------------------|
| `raw_data.png`             | Исходные данные                     |
| `processed_data.png`       | Данные после очистки                |
| `features_data.png`        | Значение и скользящие статистики    |
| `anomaly_distribution.png` | Распределение меток аномалий        |
| `dataset_summary.png`      | Сводный отчёт по набору данных       |

```
reports/
├── before/                  # снимок для выступления (не трогать)
│   ├── NAB/
│   ├── KPI/
│   ├── PROMETHEUS/
│   └── combined/
└── current/                 # python main.py пишет сюда
    ├── NAB/
    ├── KPI/
    ├── PROMETHEUS/
    └── combined/
```

## Запуск

После любой команды данные проходят весь конвейер (RAW → PROCESSED → UNIFIED →
признаки → отчёты), сохраняются в Parquet/CSV, а в консоль выводится сводка.

### NAB

```bash
# обработать ВСЕ файлы из datasets/raw/NAB (рекурсивно)
python main.py nab
# или указать конкретные файлы/папки:
python main.py nab datasets/raw/NAB/sample_nab_ec2_cpu_utilization.csv
python main.py nab path/to/folder another/file.csv
```

### KPI

```bash
# обработать ВСЕ файлы из datasets/raw/KPI
python main.py kpi
python main.py kpi datasets/raw/KPI/sample_kpi_finals.csv
```

### Prometheus

```bash
python main.py prometheus http://185.28.85.183:9090 container_cpu_usage_seconds_total
# несколько запросов и настройка диапазона:
python main.py prometheus http://185.28.85.183:9090 \
    container_cpu_usage_seconds_total container_memory_usage_bytes \
    --step 30 --range 7200
```

### Общий запуск по трём источникам (`all`)

Объединяет все источники в **один большой ML-набор** и строит отчёты по каждому
источнику + общий:

```bash
# NAB (datasets/raw/NAB) + KPI (datasets/raw/KPI); Prometheus — опционально
python main.py all

# с Prometheus:
python main.py all \
    --prom-url http://185.28.85.183:9090 \
    --prom-query node_cpu_seconds_total node_memory_MemAvailable_bytes

# можно переопределить пути источников:
python main.py all --nab path/to/nab_dir --kpi path/to/kpi_dir
```

### Общие опции

```bash
python main.py -v all                 # DEBUG-логи
python main.py --no-viz all           # без построения графиков
```

### Подготовка данных для обучения моделей обнаружения аномалий

В рамках работы реализован ETL-конвейер (Extract — Transform — Load),
обеспечивающий подготовку обучающих выборок для моделей обнаружения аномалий
в системах мониторинга микросервисов. Конвейер решает задачу унификации
разнородных источников телеметрии и формирования согласованного признакового
пространства.

**Источники данных.** В качестве источников использованы: эталонный
бенчмарк NAB (Numenta Anomaly Benchmark), набор KPI Anomaly Detection
(NetManAIOps), а также «живая» телеметрия из системы мониторинга Prometheus,
получаемая через HTTP API. Такой выбор обеспечивает сочетание размеченных
эталонных данных (для валидации) и реальных промышленных метрик.

**Архитектура конвейера.** Обработка организована по трёхуровневой модели
хранения: RAW (исходные данные без изменений), PROCESSED (очищенные и
нормализованные данные) и UNIFIED (единый набор с инженерными признаками).
Подобное разделение соответствует практикам Data Engineering (medallion
architecture) и обеспечивает воспроизводимость и аудируемость преобразований.

**Унификация.** Все источники приводятся к единой схеме
(`timestamp`, `service`, `metric_name`, `value`, `label`, `source`), что
позволяет обучать модели на объединённой выборке независимо от происхождения
данных. Для метрик Prometheus сохраняется исходный набор меток, что исключает
потерю информации о типе и контексте метрики.

**Инженерия признаков.** Для каждого временного ряда рассчитываются скользящие
статистики (среднее, СКО, минимум, максимум по окнам 5 и 15) и разностные
характеристики (приращение и относительное изменение). Полученное признаковое
пространство ориентировано на алгоритмы обнаружения аномалий без учителя,
в первую очередь Isolation Forest.

**Форматы и инструменты.** Основным форматом хранения выбран колоночный формат
Apache Parquet, обеспечивающий компактность и сохранение типов; CSV используется
для экспорта. Конвейер реализован на Python 3.12 с использованием pandas, numpy,
requests; визуализация выполнена средствами matplotlib.

**Результаты этапа.** Сформирован автоматизированный и расширяемый конвейер
подготовки данных, который служит основой для следующего этапа исследования —
обучения и сравнительного анализа моделей машинного обучения для обнаружения
аномалий в микросервисных системах.
